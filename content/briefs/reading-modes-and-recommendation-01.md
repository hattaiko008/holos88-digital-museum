# HOLOS 88｜READING MODES & RECOMMENDATION 01

更新日：2026-09-24  
状態：20記事の仮展示を読んだ後の編集設計

## 結論

現在見えてきた5つは、主題を分けるカテゴリーではない。

**記事の形式、深さ、体温、読後に向かう場所が異なる5つのReading Mode**として扱う。

自然、哲学、動物、政治、AI、食、天体などの主題カテゴリーは別に持つ。一つの記事は複数の主題へ属せるが、Reading Modeは原則として一つを中心にする。

## 5つのReading Mode

### 01｜MUSEUM ESSAY

**ECHOの博識な学びが多い文章**

- 事実、歴史、書籍、論文、人物、物を深く辿る
- SOURCE DESKを持つ
- 読了時間は比較的長い
- 梅棹忠夫、モース、レヴィ＝ストロース、岡本太郎、AIと意識など

表示は静かで密度を持たせる。本文幅を安定させ、図版、注、資料の窓を使う。

### 02｜MICHIKUSA ESSAY

**一つの記事から生まれた考察**

深い版と軽い版を分ける。

- `DEEP MICHIKUSA`：思想、政治、倫理、社会へ深く入る
- `SMALL MICHIKUSA`：語源、道具、一枚の絵、食べもの、季節の言葉などを短く辿る

MICHIKUSAは余談ではない。記事から別の記事が生まれ、元の記事へ戻るHOLOSの探索方法そのもの。

### 03｜FIELD NOTES

**hachicoの日記、呟き、暮らしの断片**

独立した大きな柱にはしない。HOLOSが知識だけの場所にならないための呼吸として置く。

- 雨、犬や猫、馬、台所、買い物、音、匂い
- 更新頻度を義務にしない
- 短くてもよい
- 無理に学びや結論へつなげない

日記一覧をHOMEの主要棚にせず、記事のあいだ、季節の入口、hachicoのページで静かに読めるようにする。

### 04｜ALMANAC OF LIFE

**hachicoの暦、季節、養生、星、食、装いのエッセイ**

無料記事は、有料版の切り売りではなく入口になる一つの読み物として成立させる。

```text
PUBLIC WINDOW
季節の短い読み物
    ↓
SEASONAL LETTER / 880円
ひとつの季節を深く読む
    ↓
28 DAYS / 1,880円
自分の記録と月・季節を重ねる
    ↓
THE THIRD VOICE / 3,880円
見えてきた問いを別の角度から考える
```

販売導線は本文途中へ置かず、読み終えた人が「もう少し一緒に歩きたい」と思った場所へ静かに置く。

### 05｜MARKET WINDOW

**市場からLifeを見る定点観察**

- PREDICTではなくOBSERVE
- PROFITではなくRELATIONSHIP
- 数字を、食卓、仕事、エネルギー、政治、土地へ戻す
- 公開日時と事実確認日を明示する

ニュース一覧にはせず、時点を持つ標本として保存する。

## TOP｜第1層

5つを同じ大きさのカードにしない。

### 1｜COVER

その時のHOLOSを代表する一つの強い窓。形式は固定しない。MUSEUM ESSAYの日も、ALMANACやFIELD NOTEの日もある。

### 2｜NOW READING

編集部がいま手渡したい3〜5本。深い記事、軽い記事、季節の記事を混ぜ、毎回同じ比率にしない。

### 3｜FOLLOW A THREAD

記事ではなく関係から入る。

- CARD → MEMORY → AI
- SEED → TIME → GERMINATION
- GIFT → RELATIONSHIP → ECONOMY
- TARO → JŌMON → WILD MIND

一つの線を選ぶと、3〜6本の記事が小さなJourneyとして現れる。

### 4｜BY RHYTHM

その日の読みたい温度から選べる入口。

- 5 MINUTES｜少しだけ道草
- 15 MINUTES｜ひとつの窓
- DEEP DIVE｜深く潜る
- WITH THE SEASON｜季節と読む
- FROM THE MARKET｜市場から見る

「忙しい人向け」とは書かない。読書の長さに優劣をつけない。

### 5｜ALMANAC / LETTER

現在の季節の無料記事を一つ見せ、その先に880 / 1,880 / 3,880円の3段階を説明する専用入口を置く。

### 6｜MUSEUM / ARCHIVE

主題、人物、場所、時代、Object、Relationshipから探す奥の棚。記事数が増えるほど価値が高くなる場所。

## 下層｜記事ページ

記事ページはReading Modeごとに同じ顔へ揃えすぎない。ただし、次の骨格は共通にする。

- HOLOS 88へ戻る
- Reading Modeと主題タグ
- タイトル、著者、公開日、更新日
- 本文
- 必要な記事だけSOURCE WINDOW
- 必要な記事だけSATORI'S VIEW
- MICHIKUSA
- 自分のLifeへ戻る小さな出口

## MICHIKUSAの3方向

記事末尾のおすすめは、単純な「次の記事」や同カテゴリーの自動表示にしない。

### NEAR｜近くへ

同じ人物、物、出来事をもう少し深く読む。

### SIDEWAYS｜横へ

違う主題に見えるが、同じ関係を持つ記事へ渡る。HOLOSらしさが最も現れる道。

### RETURN｜Lifeへ

深い記事のあとに、季節、動物、食、短いFIELD NOTEなど、身体と暮らしへ戻る。

すべての記事で三方向を機械的に埋める必要はない。二つで十分な場合も、一つだけ強い道を置く場合もある。

## 好みに応じたおすすめ

### 公開初期

編集者が関係を選ぶ。閲覧履歴を追わなくても、記事そのものの主題、Reading Mode、温度、関係から推薦できる。

### 次の段階

利用者が開いた記事から、端末内だけで次を少し変える。

- 深い記事をよく読む
- 季節の記事をよく読む
- 動物から入ることが多い
- AI、思想、歴史へ進むことが多い

ログインなし、外部送信なしを初期値にする。推薦理由を短く表示する。

> 梅棹忠夫の記事を読んだから。  
> 「記録が関係をつくる」という同じ糸を持つ記事です。

クリック数だけで似た記事を並べず、本人がまだ開いていない遠い窓を一つ混ぜる。

## 記事データへ持たせるもの

```text
reading_mode: museum_essay / michikusa_deep / michikusa_small /
              field_note / almanac / market
depth: light / medium / deep
reading_minutes: number
subjects: []
people: []
places: []
periods: []
objects: []
relationships: []
season: optional
recommendations:
  near: []
  sideways: []
  return: []
offer_path: optional
```

主題と形式を分けることで、カテゴリーが増えても破綻しない。

## hachicoの日記について

現時点の判断は、**廃止しない。義務化しない。大きく掲げすぎない。**

FIELD NOTESがあることで、Museum Essayで得た知識が、雨、馬、猫、台所、晩ごはんへ帰ってくる。記事として弱い日は公開しなくてよい。短い一場面として残したい日だけ置く。

HOLOSの価値は、すべてを重い知識へ変えることではない。

世界を遠くまで見たあと、今日のLifeへ戻れることにある。
